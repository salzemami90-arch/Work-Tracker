  1. Browser interface: enter work and select Save.
  2. Local application: validate and save the update with its history.

04

Each feature has a clear implementation

Projects, goals, and flexible steps

Create, edit, reorder, complete, defer, and move work between goals in the same project. Optional reason and assistant fields accompany new work or a change.

Save the change and its history event together. Goal completion does not close the project or complete child steps. Recoverable removal archives a step without erasing its status, dates, notes, or prior achievements; restoring it uses the original dates.

Summaries, issues, and My Notes

Keep dated entries by kind. Distinguish when earlier work happened from when it was recorded. Show Latest Summary, chronological Activity, and separate general project notes without converting text into tasks. Each goal and step also has dated Notes & updates for what happened and what was encountered.

PRD: Progress History · Project Notes
Files: tracker/service.py · static/js/render.js
Overview, dates, and achievements

Today includes pending work planned for today or earlier. This Week includes unfinished work from earlier weeks. Preserve the original date and label older work Carried over until completion, deferral, or explicit rescheduling.

Deadlines are separate from planned dates. Weeks run Sunday–Saturday; Upcoming covers seven days. Keep step and goal achievements separate and avoid counting repeated completions of one item twice in the same period.

Local requests and safe saves

Listen only on the laptop loopback address. Use same-origin request checks and a local request token. Keep user data outside publicly served assets and render user content as text.

If saving fails, keep the draft and show an error. A stale tab cannot overwrite newer work; a repeated request cannot duplicate a committed achievement.

05

Paused projects keep their context

Accepted: pause the work views, preserve the context

Temporarily exclude a paused project’s work from Today, This Week, and Active Goals. Keep the project, notes, history, and historical achievements available with a Paused label.

Keep deadlines visible in Upcoming/Overdue with that label. Resume using the original dates, including carried-over work. No task status or date is rewritten.

Accepted by the learner. This display rule is part of the requirements.

06

Daily saving and portable recovery

Save

Write a change to the app’s local database. Restarting the program reads it again.

Export Backup

Download all records in a dated JSON file. Choose where to keep that separate copy.

Restore Backup replaces a full snapshot

1

Choose and validate

Check format, dates, IDs, and relationships.

2

Preview and confirm

Review counts and the backup date; explicitly confirm replacement.

3

Save a recovery copy

Write the current data in the same restorable JSON format.

4

Restore together

Apply all records in one transaction. Failure preserves current data.

Restore is replacement, not merging. If the safety copy fails, replacement stops.

A copy on the same laptop does not protect against losing that laptop. The user chooses any additional backup location. The app does not upload data.

Storage paths and implementation

data/tracker.sqlite3 holds private working data. backups/pre-restore-… .json holds safety copies. Exported downloads go where the browser/user chooses.

Export uses a consistent snapshot. Restore revalidates the file and current revision. There is no import-only size limit that rejects a valid app export.

PRD: Local Data and Backup
Files: tracker/storage.py · tracker/backup.py
07

Evidence required before calling it working

  1. Follow the work: complete a step, add new work, move it, and retain the original achievement.
  2. Cross date boundaries: yesterday’s and earlier weeks’ unfinished work remains with its original date. Pause hides active work while retaining labeled deadlines and achievements; resume restores work using original dates.
  3. Restart the actual process: recover summaries, notes, issues, relationships, and language from the same test database.
  4. Export and restore: compare all records in an isolated database and test the safety copy, including a valid backup larger than 10 MiB.
  5. Exercise failure: reject invalid files and stale tabs; roll back partial saves; prevent duplicate committed requests.
  6. Review both languages: check forms, direction, errors, keyboard access, and offline operation after setup.

Planned verification, not completed results. Use fictional test data; do not test on personal working records.
